# Review guide: Plan of Action and Milestones (`poam_skill.md`)

> **Reference Sub-Skill:** This document is a component reference specification under `<SKILL_DIR>/subskills/` and is invoked through the parent `compliance` skill ([../SKILL.md](../SKILL.md)).

Use after the workflow in [../SKILL.md](../SKILL.md) has run. Outputs:

- `<TARGET_FOLDER>/ato_artifacts/POAM/Plan_of_Action_and_Milestones.xlsm` (from
  `<SKILL_DIR>/templates/poam/POAM_Export_Template.xlsm`, 41 columns per item starting at row 8)
- `<TARGET_FOLDER>/ato_artifacts/POAM/Plan_of_Action_and_Milestones.yaml` (generated by
  `src/compliance_engine/generate_compliance_artifacts.py`)

Items come only from these sources:

1. `poam_items` declared in `compliance_config.yaml`.
2. Checkov and Semgrep findings (when the tools are on `PATH`) and `*.sarif` files in the target
   folder.
3. Terraform files the parser could not read (CA-2/RA-5 boundary discovery gaps).
4. `scc_findings` recorded in the inventory.
5. Rules in `src/compliance_engine/poam_rules.py` that test the inventory (for example, an
   instance with a public IP address, or a setting the extractor could not determine).

With none of these, the POA&M is empty; the generator adds no filler rows.

## 1. Check that each item is real

- Trace every item to one of the sources above. Remove or flag anything you cannot trace.
- Scanner outages are not security weaknesses. They are left out of the POA&M unless
  `include_scanner_failures_in_poam` is true; check the generator log for
  `Scanner outage detected`, because an outage means part of the code was not scanned.
- Do not add assessment milestones that have not happened (penetration tests, tabletop
  exercises) as if they were findings.

## 2. Check dates

- The generator schedules items from the effective date by severity (30 days for High findings,
  longer for lower severities). Check each scheduled completion date against the remediation
  timeframes the baseline or the AO requires.
- The validator warns about open items whose scheduled date is today or earlier, and about dates
  it cannot parse.

## 3. Check mitigations

- Each planned mitigation names the Terraform resource, setting, or procedure to change, not a
  general promise.
- Several columns (for example, cost, resources required, and residual-risk wording) are filled
  with fixed default text. Replace those defaults with the program's real values before
  submission.

## 4. Check allowed values

- Status, severity, and risk values match the allowed values described in the workbook's
  `Glossary` and `Instructions` sheets and the import format your GRC system (for example, eMASS)
  expects.

Edits to the generated files are overwritten by the next `generate` or `validate --fix` run.

## Example requests

- "Check that the POA&M items match the scanner results."
- "Check the POA&M dates against our remediation timeframes."
- "Make sure the POA&M has no invented findings."
